# Audit verification

Read the spec, design brief, pre-build scenarios, UI review, and raw test output. Do not trust prose claims without command exit codes or browser evidence. Check requirement coverage, browser and accessibility states, trust-boundary risks, failures, missing evidence, and test independence limits. Cite evidence for findings. Report `PASS: evidence`, `REVISE: findings`, or `BLOCKED: reason`. State the next action. Record the verdict with the stage output. Do not claim independent review when the author performs the audit.
