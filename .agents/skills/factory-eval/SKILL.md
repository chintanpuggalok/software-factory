# Evaluate the workflow

1. Define the behavior, baseline, test cases, and pass criteria before changing the workflow.
2. Include a normal case, a failure case, and a case that tests an approval or permission boundary.
3. Run the cases with the available tools. Record inputs, outputs, checks, limitations, and actual cost when known.
4. Compare results with the baseline. Report regressions and uncertainty. Do not claim a cost or quality gain without evidence.

Use an independent reviewer only when delegation is authorized. Do not claim this skill enforces gates or measures token costs by itself.
