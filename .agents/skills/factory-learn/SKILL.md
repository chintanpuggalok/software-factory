# Learn from the work

1. Review the task outcome, failures, corrections, and evidence. Read relevant existing lessons.
2. Identify recurring causes. Separate confirmed facts from hypotheses and taste preferences.
3. Consider prevention in this order: architecture, types, automated checks, tests, then instructions. Use the simplest effective option.
4. Apply changes only within authorized scope. Test that a check detects the prior failure when practical. Record the evidence and remaining gaps.
5. Send a changed or new skill and its test evidence to the matching audit skill. Adopt it only after `PASS: evidence`. If no audit matches, record the diff and evidence beside the skill.
6. Send taste feedback to `factory-taste` when relevant. Use `factory-preferences` for confirmed user-wide preferences. Keep only lessons that can help future work.

Do not change goals, permissions, budgets, evaluation rules, or deployment targets without authorization. Do not claim an improvement without evidence.
