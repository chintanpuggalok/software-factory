# Learn from the work

1. Review the task outcome, failures, corrections, and evidence. Read relevant existing lessons.
2. Identify recurring causes. Separate confirmed facts from hypotheses and taste preferences.
3. Consider prevention in this order: architecture, types, automated checks, tests, then instructions. Use the simplest effective option.
4. Before changing a skill or workflow, define the expected behavior, baseline, test cases, and pass criteria. Include a normal case, a failure case, and a case that tests an approval or permission boundary.
5. Run the cases with the available tools. Record inputs, outputs, limitations, and actual cost when known. Compare with the baseline and report regressions. Do not claim a cost or quality gain without evidence.
6. Send the changed skill and its evidence to the matching audit skill. Adopt it only after `PASS: evidence`. If no audit matches, record the diff and evidence beside the skill.
7. Send taste feedback to `factory-taste` when relevant. Keep only lessons that can help future work.

Do not change goals, permissions, budgets, evaluation rules, or deployment targets without authorization. Use an independent reviewer only when delegation is authorized.
