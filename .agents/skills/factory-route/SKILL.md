# Route the task

1. Read the goal, authorized scope, project state, and relevant constraints.
2. Select the entry point: idea, feature, bug, design, refactor, verification, or release. Do not run every stage for a small change.
3. For a bug, feature, or refactor, read the matching file in `references/`. Use only the selected playbook. For other tasks, define the required evidence for the selected route.
4. Identify the next skill, its audit, required evidence, and dependencies. Record the reason and the next action.
5. Load only the selected skill and the context it needs.

This skill recommends a route. It does not enforce execution or grant permission to spend, install, delegate, or deploy.
