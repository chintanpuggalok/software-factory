# Review the experience

1. Read the approved design brief and available taste index. If no index exists, use confirmed project preferences and report the gap. Load only taste records relevant to this review.
2. Inspect the running interface in a browser when available. Check core flows, target screen sizes, accessibility, loading, empty, and error states.
3. Compare hierarchy, spacing, typography, color, interaction feedback, and consistency with the brief. Capture evidence when possible.
4. Report findings and fix authorized issues. Use the approved brief and relevant taste for reversible choices. Ask only for a consequential user decision that blocks progress.

If browser inspection is unavailable, report that gap. Do not claim that tests prove visual quality. Send the evidence to `audit-visual`. Advance only after `PASS: evidence`. At the stage change, hand over the goal, confirmed decisions, artifact paths, open questions, next action, and review evidence. Load `factory-taste` only when recording or applying taste.
